# Ultra-Low-Power LoRa/GPS Tracker Node — 2-Layer PCB

A complete, fabrication-ready 2-layer PCB for a battery-powered LoRa (433 MHz) /
GPS tracker: **ESP32‑WROOM‑32E**, **Ai‑Thinker Ra‑02 (SX1278)**, **DS3231MZ RTC
with CR1220 backup**, **microSD**, a **high-side P‑MOSFET power gate** for the
GPS + SD rail, a **vibration wake sensor** input and **UART programming/flashing
headers**.

Everything (placement, routing, ground pours, Gerber, Excellon, KiCad board,
BOM, DRC report) is **generated by the Python toolchain in `pcbgen/`** — there is
no hand-drawn geometry to drift out of sync, and the Gerbers, drill files and
`.kicad_pcb` are guaranteed to describe exactly the same copper.

## 2. Board specification

| Parameter | Value |
|---|---|
| Dimensions | 60.0 × 45.0 mm |
| Stack-up | 2 layers, FR4, 1.6 mm, 1 oz (35 µm) copper |
| Finish | green solder mask, white silkscreen, lead-free HASL |
| Mounting | 4 × M2.5, 2.7 mm NPTH, 3 mm inset from each corner |
| Power / GND tracks | 0.60 mm (24 mil) |
| Signal tracks | 0.254 mm (10 mil) |
| Minimum clearance | 0.20 mm (8 mil) |
| Vias | 0.60 mm pad / 0.30 mm drill (0.15 mm annular ring) |
| Minimum drill | 0.30 mm |
| Ground | flood pour on **both** layers + stitching vias (2.4 mm lattice) |

The router works on a **0.20 mm grid with a +0.035 mm safety margin** on every
clearance, so the finished copper is always at or above the 0.20 mm rule — the
DRC re-checks the *finished* copper with exact geometry, not the grid.

### Antenna keep-out

* **ESP32‑WROOM‑32E**: the module body sits at y = 0…25.5 mm, i.e. the PCB
  antenna section **overhangs the top board edge** exactly as Espressif
  requires. The antenna area (`x 6.5…24.5`, `y 0…5.2`) carries **no copper on
  either layer** — enforced three ways: the router blocks it, the pour masks it
  (plus a 0.3 mm safety ring), and the DRC verifies that no track, pad, via or
  pour polygon enters it.
* **Ra‑02**: the IPEX connector end (`x 39.5…46.5`, `y 22.5…24.6`) is kept clear
  on both layers, and the bottom layer under the module is solid ground.

## 4. Layout notes

* **ESP32** in the upper-left, antenna overhanging the top edge, with its bulk
  (C4) and EN RC (R1/C3) parts immediately on the left edge.
* **RTC** (U3) top-centre, its I²C pull-ups (R7/R8), decoupling (C5) and wake
  pull-up (R9) alongside; the CR1220 holder is on the **bottom** side under the
  ESP32 module, so the cell can be changed without touching the top side.
  `BAT1`'s bottom-side pads are reachable from the bottom and its connection to
  U3.6 is routed as a short top-layer drop that vias over.
* **Ra‑02** lower-right with the IPEX end up; SPI and CS run as a short bus
  from the ESP32 right-hand column, and the module is surrounded by ground.
* **microSD** upper-right with the card mouth facing the right board edge, so a
  card can be inserted after assembly.
* **Power gate**: Q1 (AO3401A) bottom-left next to the battery connector; R3
  pulls the gate to `3V3` (off by default, ~0 µA in sleep once IO25 is parked)
  and R6 feeds the gate from IO25.
* **Decoupling**: C1 10 µF bulk + C2 100 nF on `3V3` at the ESP32, C4 10 µF at
  the module supply pins, C3 100 nF on EN, C5 100 nF on the RTC, C6 100 nF on
  `VCC_SW`.
* **Ground**: continuous pour on both layers, 0.30 mm thermal reliefs with four
  0.40 mm spokes on every GND pad, and ~2.4 mm-spaced stitching vias wherever
  both layers have plane copper.

## 5. Toolchain (`pcbgen/`)

| Module | Responsibility |
|---|---|
| `board.py` | Design rules, netlist, placement — the single source of truth |
| `footprints.py` | Footprint library (Espressif land pattern, Ra‑02, SOIC‑8, SOT‑23, 0805, microSD, headers, CR1220, tact switch) |
| `router.py` | Grid autorouter: exact pad/raster obstacles, dilation by (track/2 + clearance), 16‑direction A* with bend penalty, vias only where both layers are clear, tree (Prim/MST) net construction |
| `pour.py` | Ground pour: obstacle mask, thermal reliefs, island removal, run‑merged polygon extraction, stitching‑via placement |
| `fab.py` | Gerber RS‑274X + Excellon output, **and the DRC** (clearance, connectivity, annular ring, hole spacing, edge, antenna keep‑out, silkscreen) |
| `gerber.py` | RS‑274X writer and the stroke font used for the silkscreen |
| `kicad.py` | KiCad 8 `.kicad_pcb` writer (footprints, tracks, vias, pre‑filled zones, rule areas) |
| `plot.py` | PNG preview renderer |

The autorouter is deterministic: same input, same board. `out/route_cache.json`
holds the routing so the export steps can be re-run in seconds.

### What the DRC checks

1. **Clearance** — exact polygon distance between every pair of copper items on
   each layer (0.20 mm; 0.15 mm where a via is involved, as vias are round and
   sit in a mask-free pad).
2. **Connectivity** — union-find over the finished copper: each signal net must
   be exactly one island, and every pad must be present.
3. **Drills** — annular ring ≥ 0.15 mm, hole-to-hole ≥ 0.30 mm, minimum drill.
4. **Board edge** — ≥ 0.30 mm copper-to-outline.
5. **Antenna keep-outs** — no copper of any kind inside the RF zones.
6. **Silkscreen** — the legend actually emitted to the Gerber is clipped against
   the board edge and every solder-mask opening (0.15 mm silk clearance), and the
   DRC then verifies the emitted strokes.

## 6. Manufacturing checklist

1. Upload `out/LoRaTracker_Gerbers.zip` (or select the files in
   `out/gerbers/`) — 2 layers, 1.6 mm, 1 oz, green mask, white silkscreen, HASL.
2. Confirm in the fab's preview: board 60 × 45 mm, 4 × 2.7 mm NPTH mounting
   holes, 0.3 mm vias.
3. Assembly: top side is the main side (ESP32, Ra‑02, RTC, microSD, passives);
   only the CR1220 holder (BAT1) goes on the bottom side. `out/LoRaTracker-pos.csv`
   gives positions and rotations.
4. Solder the ESP32 module **last** and keep the 433 MHz antenna area free of
   copper, solder residue and enclosure metal.

## 7. Known deviations / notes

* `J1.9` (microSD card-detect switch) is **not connected** — the supplied netlist
  does not include it, and the pad is left unconnected. Wire it to a spare GPIO
  if card-detect is wanted.
* The Ra‑02 rotates 0° with the IPEX connector at the top of the module; verify
  the pad‑1 chamfer on the actual module before reflow.
* The DS3231MZ is a **chip** (SOIC‑8), not a module — it needs the CR1220 holder
  as the backup cell, exactly as wired (`RTC_VBAT`).
* Gerber files use the X2 `%TF.FileFunction%` attribute, which every modern fab
  reads; the `.GTL/.GBL/.GTS/.GBS/.GTO/.GBO/.GKO` extensions are the classic
  Protel set so no manual layer mapping is needed.
